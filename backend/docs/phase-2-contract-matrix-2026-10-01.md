# Phase 2 — EduGD contract matrix and feature classification

Date: 2026-10-01  
Scope: repository evidence and disposable localhost evidence only. Hosted
providers, production resources, real credentials, and physical Android devices
were not accessed.

## Evidence boundary

The live-local evidence consists of the successful disposable PostgreSQL stack,
Flask readiness, Vite proxy traffic, and 12 Playwright tests across Chromium
desktop and mobile. The frontend quality command also passed with 53 unit tests.
No hosted, Redis-provider, physical-device, hardware-attestation, telephony, or
backup/restore evidence was supplied in this phase. Those claims remain
`UNVERIFIED` or `BLOCKED`; local tests do not substitute for them.

Source contracts were read from `backend/app/routes`, `backend/app`,
`frontend/school-policy-admin/src/services`, `frontend/school-policy-admin/src/schemas`,
the migration directory, Android tests, and the referenced CI/deployment files.

## Classification summary

| Classification | Count | Meaning in this matrix |
|---|---:|---|
| IMPLEMENTED | 4 | Direct repository and/or live-local evidence supports the stated contract. |
| MISSING | 0 | No item is called missing solely because evidence is absent. |
| CONTRADICTORY | 0 | No new contradiction was asserted without direct source comparison. |
| STALE | 0 | Historical documentation was not treated as current proof. |
| UNVERIFIED | 18 | The contract exists or is partly tested, but the required evidence class is incomplete. |
| BLOCKED | 6 | Physical, hosted, backup/restore, or Redis evidence is required and unavailable. |

The counts are an audit snapshot, not a claim that unverified behavior is
correct. A verified defect must be recorded separately with reproduction
evidence before a remediation prompt or code change is proposed.

## Required next remediation candidates

No implementation change is authorized by this matrix alone. The smallest
candidate evidence groups are:

1. Add disposable Redis orchestration and fail-closed live checks.
2. Add live disposable policy, token, Block/clear, application, and
   administrator-management mutation scenarios.
3. Supply approved staging backup/restore and read-only privilege evidence.
4. Supply exact Android handset, DPC signing, attestation, telephony, and
   device-owner evidence.

Each group requires its own read-only reproduction, proposed diff, approval,
focused tests, and redacted audit result.
